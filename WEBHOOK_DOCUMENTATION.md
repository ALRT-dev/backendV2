# Webhook API Documentation

## Overview

This webhook allows external tools like N8N to create hazards in the system. The webhook endpoint provides similar functionality to the admin `createHazardForAdmin` controller but is designed for automation tools.

## Security

The webhook is protected by **6 layers of enterprise-grade security** to prevent abuse and ensure system reliability.

### Security Layers

1. **Burst Protection**: Maximum 10 requests per minute (prevents rapid attacks)
2. **Rate Limiting**: Maximum 100 requests per 15 minutes (main defense)
3. **Speed Limiting**: Gradual slowdown after 50 requests (warning system)
4. **Daily Quota**: Maximum 1,000 requests per day (prevents sustained abuse)
5. **API Key Authentication**: Validates authorized clients with audit logging
6. **Request Validation**: Schema validation prevents malformed data

### What This Means for Your Client

- **Normal Usage**: No impact - limits are generous for typical workflows
- **N8N Workflows**: Can safely run every minute (1,440/day max)
- **Burst Workflows**: Up to 10 requests/minute, 100 per 15 minutes
- **Protection**: System automatically blocks if limits exceeded
- **Transparency**: Rate limit info returned in response headers

### Setting Up Security

1. **Generate a Strong API Key**

   ```bash
   # Generate a secure random API key (32 characters)
   openssl rand -base64 32
   ```

2. **Add to Environment Variables**
   Add the following to your `.env.dev` or `.env.prod` file:

   ```env
   WEBHOOK_API_KEY=your-generated-api-key-here
   ```

3. **Keep the API Key Secure**
   - Never commit the API key to version control
   - Share it securely with your client (e.g., encrypted communication)
   - Rotate the key periodically for security
   - Use different keys for different environments (dev/prod)

### Security Against Abuse

**Q: What if someone makes 1 million requests?**

**A:** The system will:

1. Block after 10 requests in 1 minute (burst protection)
2. Block after 100 requests in 15 minutes (rate limit)
3. Block after 1,000 requests in 24 hours (daily quota)
4. Log all attempts for monitoring
5. Automatically unblock after cooldown period

**Maximum Damage**: 1,000 requests per day, then complete lockout for 24 hours.

For complete security details, see `WEBHOOK_SECURITY.md`

## Endpoint

### Create Hazard via Webhook

**POST** `/api/webhook/hazards`

#### Authentication

Include the API key in the request header:

```
X-Webhook-Api-Key: your-generated-api-key-here
```

#### Request Body

```json
{
  "description": "Fire reported near residential area",
  "sourceId": "source-uuid-here",
  "title": "Residential Fire Alert (optional)",
  "latitude": -33.8688,
  "longitude": 151.2093,
  "locationName": "Sydney, NSW",
  "categoryId": "category-uuid-here (optional)",
  "severity": "emergency (optional)",
  "severityBand": "emergency (optional)",
  "callToAction": "Evacuate immediately (optional)",
  "fireStatus": "goingFire (optional)",
  "isAwsCompliant": true,
  "link": "https://example.com/source (optional)",
  "occurredAt": "2025-12-14T10:30:00Z (optional)",
  "expiresAt": "2025-12-15T10:30:00Z (optional)"
}
```

#### Location Requirements

You **MUST** provide either:

- **Point location**: `latitude` AND `longitude`
- **Bounding box**: `northeastLat`, `northeastLng`, `southwestLat`, `southwestLng`

#### Field Descriptions

| Field            | Type    | Required | Description                                            |
| ---------------- | ------- | -------- | ------------------------------------------------------ |
| `description`    | string  | ✅       | Description of the hazard (1-1000 chars)               |
| `sourceId`       | string  | ✅       | UUID of the hazard source                              |
| `title`          | string  | ❌       | Hazard title (auto-generated by AI if not provided)    |
| `latitude`       | number  | ❌\*     | Latitude (-90 to 90)                                   |
| `longitude`      | number  | ❌\*     | Longitude (-180 to 180)                                |
| `locationName`   | string  | ❌       | Human-readable location name                           |
| `northeastLat`   | number  | ❌\*     | Northeast corner latitude                              |
| `northeastLng`   | number  | ❌\*     | Northeast corner longitude                             |
| `southwestLat`   | number  | ❌\*     | Southwest corner latitude                              |
| `southwestLng`   | number  | ❌\*     | Southwest corner longitude                             |
| `categoryId`     | string  | ❌       | Hazard category UUID (auto-detected if not provided)   |
| `severity`       | enum    | ❌       | `emergency`, `watch_and_act`, `advice`, `unknown`      |
| `severityBand`   | enum    | ❌       | `emergency`, `alert`, `warning`, `info`                |
| `callToAction`   | string  | ❌       | What people should do (auto-generated if not provided) |
| `fireStatus`     | enum    | ❌       | `goingFire`, `beingControlled`, `underControl`         |
| `isAwsCompliant` | boolean | ❌       | Whether this follows AWS standards                     |
| `link`           | string  | ❌       | URL to source information                              |
| `occurredAt`     | string  | ❌       | ISO 8601 datetime when hazard occurred                 |
| `expiresAt`      | string  | ❌       | ISO 8601 datetime when hazard expires                  |

\*At least one location option (lat/lng OR bounding box) is required

#### Error Responses

**401 Unauthorized** - Missing or invalid API key

```json
{
  "message": "Webhook API key is missing"
}
```

**403 Forbidden** - Invalid API key

```json
{
  "message": "Invalid webhook API key"
}
```

**429 Too Many Requests** - Rate limit exceeded

```json
{
  "error": "Too many webhook requests",
  "message": "You have exceeded the rate limit of 100 requests per 15 minutes. Please try again later.",
  "retryAfter": "15 minutes"
}
```

**429 Burst Protection** - Too many requests per minute

```json
{
  "error": "Too many requests in short time",
  "message": "You are sending requests too quickly. Maximum 10 requests per minute allowed.",
  "retryAfter": "1 minute"
}
```

**429 Daily Quota** - Daily limit exceeded

```json
{
  "error": "Daily quota exceeded",
  "message": "You have exceeded the daily quota of 1000 requests. Please try again tomorrow.",
  "retryAfter": "24 hours"
}
```

**400 Bad Request** - Validation error

```json
{
  "message": "Either latitude & longitude or northeast & southwest bounds must be provided"
}
```

#### Rate Limit Headers

All responses include rate limit information:

```http
RateLimit-Limit: 100
RateLimit-Remaining: 73
RateLimit-Reset: 1639478400
Retry-After: 900
```

Use these headers to implement smart retry logic in your N8N workflow.

## N8N Integration Example

### 1. HTTP Request Node Configuration

**Method**: POST  
**URL**: `https://your-api-domain.com/api/webhook/hazards`

**Headers**:

```json
{
  "Content-Type": "application/json",
  "X-Webhook-Api-Key": "={{$env.WEBHOOK_API_KEY}}"
}
```

**Body**:

```json
{
  "description": "={{$json.description}}",
  "sourceId": "={{$json.sourceId}}",
  "latitude": {{$json.latitude}},
  "longitude": {{$json.longitude}},
  "locationName": "={{$json.location}}",
  "severity": "emergency"
}
```

### 2. Setting Up Environment Variable in N8N

1. Go to Settings → Environment Variables
2. Add: `WEBHOOK_API_KEY=your-generated-api-key-here`
3. Use `{{$env.WEBHOOK_API_KEY}}` in your HTTP Request node

### 3. Implementing Retry Logic in N8N (Recommended)

Add error handling to respect rate limits:

1. **Add "Error Trigger" node** after HTTP Request
2. **Add "Wait" node** with expression: `={{$json.retryAfter || '60s'}}`
3. **Add "HTTP Request" node** to retry the request
4. **Set max retry attempts**: 3

Example workflow:

```
[Trigger] → [HTTP Request] → [Success]
              ↓ (on error)
          [Check Status Code]
              ↓ (if 429)
          [Wait] → [Retry HTTP Request]
              ↓ (if other error)
          [Log Error]
```

## Best Practices

1. **Respect Rate Limits**:

   - Maximum 10 requests/minute (burst)
   - Maximum 100 requests/15 minutes
   - Maximum 1,000 requests/day
   - Check `RateLimit-Remaining` header before sending requests

2. **Implement Retry Logic**:

   - Check for 429 status code
   - Use `Retry-After` header value for wait time
   - Implement exponential backoff
   - Maximum 3 retry attempts recommended

3. **Error Handling**:

   - Log all failures for debugging
   - Alert on repeated failures
   - Validate data before sending

4. **Optimize N8N Workflows**:

   - Batch operations when possible
   - Avoid polling intervals < 1 minute
   - Use webhook triggers instead of polling when available

5. **Monitoring**:

   - Track success/failure rates
   - Monitor rate limit usage
   - Set up alerts for quota approaching

6. **Security**:
   - Never log the full API key
   - Rotate keys every 3-6 months
   - Use different keys for dev/prod
   - Store keys in N8N environment variables, not in workflows

## Security Considerations

### Why API Key Authentication?

- **Simple**: Easy to implement and use in N8N
- **Stateless**: No session management required
- **Secure**: Uses constant-time comparison to prevent timing attacks
- **Flexible**: Can be easily rotated without code changes

### Additional Security Recommendations

1. **Use HTTPS**: Always use HTTPS in production
2. **IP Whitelisting**: Consider adding IP whitelisting if your client has a static IP
3. **Rate Limiting**: Implement rate limiting to prevent abuse
4. **Monitoring**: Set up monitoring and alerts for unusual webhook activity
5. **Audit Logging**: Log all webhook requests with timestamps and client information

## Troubleshooting

### "Webhook API key is missing"

- Ensure the header `X-Webhook-Api-Key` is included in the request
- Check for typos in the header name (case-sensitive)
- Verify N8N environment variable is set correctly

### "Invalid webhook API key"

- Verify the API key matches the one in your `.env` file
- Check for extra spaces or hidden characters in the key
- Ensure you're using the correct environment (dev/prod)
- After 10 failed attempts, wait 1 hour before trying again

### Rate Limit Errors (429)

**"Too many requests in short time"** (Burst protection)

- You're sending more than 10 requests/minute
- Wait 1 minute before retrying
- Adjust N8N workflow to space out requests

**"Too many webhook requests"** (Rate limit)

- You've sent more than 100 requests in 15 minutes
- Wait for the time specified in `Retry-After` header
- Check `RateLimit-Reset` header for exact reset time
- Optimize workflow to reduce request frequency

**"Daily quota exceeded"**

- You've sent more than 1,000 requests today
- Wait until tomorrow (24 hours from first request)
- Consider batching data or optimizing workflow
- Contact team if you need higher limits

### How to Check Rate Limit Status

Check the response headers:

```bash
curl -I -X POST https://your-api.com/api/webhook/hazards \
  -H "X-Webhook-Api-Key: your-key"
```

Look for:

- `RateLimit-Remaining`: How many requests you have left
- `RateLimit-Reset`: When the limit resets (Unix timestamp)
- `Retry-After`: How many seconds to wait (if rate limited)

### "Invalid sourceId provided"

- The sourceId must exist in the database
- Query `/api/admin/hazards/sources` to get valid source IDs

### "Either latitude & longitude or bounds must be provided"

- You must provide either:
  - Both `latitude` AND `longitude`, or
  - All four bounding box coordinates

### N8N Specific Issues

**Request timing out**

- Server is delaying response due to speed limiting
- You're approaching rate limits
- Check `RateLimit-Remaining` header
- Space out requests more

**Workflow running slowly**

- Speed limiter is adding delays
- You've sent more than 50 requests in 15 minutes
- Wait for limit window to reset
- Reduce request frequency
